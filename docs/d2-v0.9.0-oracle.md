# D2 v0.9.0 TALA oracle

Parity work uses the released D2 v0.9.0 TALA implementation as the authority.

- Source tag: `v0.9.0`
- Source commit: `d5a51743b6d5c00f1ec6f8340003f5d5a6ba4eda`
- Release binary: `d2-v0.9.0-macos-arm64.tar.gz`
- Release archive SHA-256: `eaf6c0c143e56dd9fa97bfb6df25ea9c1ebce40245f056a0768cf1a6c15d306`
- Release binary toolchain: Go `1.27.0` (`go version -m`)

The release archive and checksum list are published at the [D2 v0.9.0 GitHub
release](https://github.com/terrastruct/d2/releases/tag/v0.9.0). The source
checkout must resolve to the commit above before it is used for comparisons.

Build a local oracle from that checkout with:

```sh
D2_SOURCE=/path/to/d2-v0.9.0 \
  ./scripts/build-d2-v090-oracle.sh
```

The oracle's JSON protocol is intentionally separate from the release binary.
For trace comparison, apply the diagnostic-only patch and build the same
oracle again:

```sh
D2_SOURCE=/path/to/d2-v0.9.0 ./scripts/apply-d2-v090-trace.sh
TALA_TRACE_JSONL=1 /path/to/oss-tala-oracle layout --tala-seeds 1 < graph.bin \
  >/tmp/tala.json 2>/tmp/tala.trace.jsonl
```

The patch emits exact IEEE-754 bit strings at every pipeline stage and writes
only to stderr. It does not alter the normal TALA protocol or release binary.

Build the source checkout's D2 CLI and compare its public TALA output with the
release binary on representative fixtures:

```sh
GOTOOLCHAIN=go1.27.0 go build -o /tmp/d2-v090-source-cli /tmp/d2-v090-source
scripts/compare-d2-v090-binaries.sh \
  /tmp/d2-official-v090/d2-v0.9.0/bin/d2 \
  /tmp/d2-v090-source-cli
```

The check compares complete SVG bytes with version metadata omitted. The
diagnostic trace patch is only used by the serialized-graph oracle and does
not affect this public-output comparison.
